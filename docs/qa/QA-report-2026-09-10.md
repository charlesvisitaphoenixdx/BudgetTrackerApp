## Bugs found and fixed

1. **Renaming an expense type to a duplicate or empty name failed silently.** The name field would show whatever invalid text the user typed after clicking away, with no error message and no visual revert — so a user could easily believe the rename "took" when it hadn't (the underlying data was actually safe; only the display was misleading). Fixed by giving each row its own editable state: an invalid rename now reverts the field to the last good value and shows an inline error ("already exists" / "can't be empty") right under that row.
2. Same root cause covered both the duplicate-name and empty-name cases (TC-08 and TC-09) — one fix resolved both.
3. **The "add new expense type" name field had no accessible label**, relying on placeholder text alone, which screen readers don't treat as a label. Added `aria-label="New expense type name"`.
